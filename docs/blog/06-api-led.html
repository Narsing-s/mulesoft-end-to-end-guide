API-Led Connectivity: Experience, Process and System APIs

API-led connectivity is an architectural approach that separates consumer experience, business processes and access to systems.

Experience API

Shapes data and interaction for a particular consumer such as a mobile app, web portal or partner.

Process API

Coordinates business logic and combines information from multiple systems without being tied to one consumer.

System API

Provides controlled access to a system of record such as a CRM, database or legacy application.

Why separation matters

It can improve reuse and isolate changes. But the layers are not a rule that every API must have three separate applications. Architecture should follow the actual business and operational requirements.

Design question: What responsibility changes independently? Put boundaries around responsibilities that need independent reuse, ownership, security or lifecycle.
