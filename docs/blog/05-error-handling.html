Mule 4 Error Handling: Continue vs Propagate

Error handling is about deciding what the application should do when a component cannot complete its normal work.

First understand the failure

A Mule error has a type and can carry a description and cause. Your handler can inspect that information and decide how to recover or return an error.

On Error Continue

Continue handles the error and allows the flow to complete successfully from the caller's perspective, using the handler's resulting message.

On Error Propagate

Propagate handles the error but keeps the failure visible to the caller. This is useful when the operation should not be considered successful.

<try>
  <http:request .../>
  <error-handler>
    <on-error-propagate type="HTTP:TIMEOUT">
      ...
    </on-error-propagate>
  </error-handler>
</try>

How to choose

Do not choose based only on the name. Ask whether the business operation should be considered successful after recovery. Also define the response body, status code, logging and correlation information.

Production habit: Never hide an error simply to make a flow look green. Recovery should be intentional and observable.
